# 지금 만들 작업: 바로 착수할 수 있는 메뉴별 태스크

**상태: 구현 완료 (사용자 승인 후)**

## 문제
현재 아래 섹션은 여러 메뉴를 한 카드의 문장과 총 제조량으로 합쳐 보여 준다. 메뉴 일부만 만들었을 때 완료를 기록할 수 없다. 아래 작업의 완료는 해당 메뉴를 만들었다는 뜻이며, 위 주문서에는 **그 메뉴 줄만 가로선으로 표시**해야 한다. 위 주문서의 `완료`는 주문 전체 처리이다.

## 바리스타가 보는 화면
1. 섹션 이름 `지금 만들 작업`을 유지한다.
2. **첫 번째 블록이 지금 착수할 일**임을 순서·시각적 강조로 표시한다. 각 블록의 큰 제목은 `카페 라떼 2잔 만들기`처럼 동사와 수량을 함께 쓴다. 관련 주문별 배분(`#126 1잔 · #128 1잔`), 사이즈·제조 옵션, 레시피에 있는 장비를 바탕으로 한 짧은 제조 키워드를 표시한다. 제조 정보가 없는 경우 지어내지 않는다.
3. 위 주문서의 묶음 이름표에는 `같이 만들기`만 표시하고 Zoro 점수는 표시하지 않는다.
4. 원래처럼 각 작업을 독립된 블록으로 보여 준다. 다른 메뉴·사이즈·제조 옵션은 별도 블록이다. 같은 조건의 잔만 한 블록으로 묶는다. 디카페인·오트밀크처럼 함께 제조할 수 없는 옵션은 별도 블록이다.
5. 제조 작업마다 서로 다른 색을 배정한다. 작업 블록과 그 작업에 포함된 위 주문서의 메뉴 줄은 같은 색의 굵은 표시선을 사용한다. 복합 주문은 메뉴 줄마다 다른 작업 색을 표시하고, 작업에 포함되지 않은 메뉴 줄은 색을 넣지 않는다. 색만으로 구분하지 않도록 표시선과 작업명을 함께 보여 준다.
6. 각 블록에 `제조 완료` 버튼을 둔다. 누르면 그 블록과 관련 주문서의 **해당 메뉴 줄들**이 완료 표시(가로선)된다. 다른 메뉴 줄과 다른 작업 블록은 그대로다. 예를 들어 라떼 2잔 블록을 누르면 #126·#128의 라떼 줄을 모두 표시한다.
7. 위 주문서의 `완료`는 주문 전체 처리이다. 아래 제조 완료는 주문서의 `완료` 버튼을 대신 누르거나 주문을 보드에서 제거하지 않는다. 위 주문서 완료도 아래의 다른 메뉴를 제조 완료로 표시하지 않는다.
8. Zoro 확인 중이거나 응답하지 않아도 1번 주문 자체의 제조 작업은 보여 준다. 확인 전에는 다른 주문을 합치지 않고, 오류 문구는 작업 제목보다 덜 강조한다. Zoro 응답이 오면 합칠 수 있는 메뉴만 추가한다.

## Zoro와 코드의 책임
- `aiserver /ai/group-orders`는 **어떤 주문이 비슷한지**에 더해 **그 주문의 어떤 메뉴가 기준 주문 메뉴와 함께 제조 가능한지**를 반환한다. 현재는 메뉴 한 쌍만 비슷해도 주문 전체를 묶으므로, 다른 메뉴가 잘못 작업에 섞일 수 있다.
- 응답에는 기존 `groups`, `scores`, `fallback`을 유지하고 `matched_menus: { 주문번호: [메뉴 ID] }`를 추가한다. 같은 메뉴는 점수 1로 처리하며, 다른 메뉴는 기존 Zoro 메뉴 쌍 점수 0.5 이상인 것만 이 목록에 넣는다. `teamktb`는 요청에 없는 주문·메뉴 ID를 무시한다.
- Zoro는 이름이 다른 메뉴 쌍의 제조 호환성만 판단한다. 같은 메뉴는 코드가 바로 묶고, 제조 불가 옵션·고장 장비는 `teamktb`가 먼저 제외한다.
- `teamktb`는 검증한 메뉴별 판단 결과와 레시피로 작업 블록·수량·순서·짧은 지시문을 계산한다. Zoro가 UI 문장을 생성하거나 버튼 상태를 관리하지 않는다.
- 응답 계약을 변경하면 양쪽 스키마·파서·테스트·계약 문서를 함께 고친다. Zoro 실패 시 작업은 1번 주문 기준으로 계속 가능해야 한다.

## 예시
`#126 카페 라떼 1잔`, `#128 카페 라떼 1잔`, `#129 아이스 아메리카노 1잔`이 함께 만들 주문으로 선택되면:

- 블록 1: `카페 라떼 2잔 만들기` · `#126 1잔, #128 1잔` · `제조 완료`
- 블록 2: `아이스 아메리카노 1잔 만들기` · `#129 1잔` · `제조 완료`

블록 1만 완료하면 #126·#128 주문서의 카페 라떼 줄에 가로선이 생긴다. 블록 2와 #129의 아이스 아메리카노 줄은 미완료이며, 세 주문의 주문서 전체 완료 상태는 그대로다. 이후 `#126` 주문서 완료를 눌러도 블록 2가 자동 완료되지 않는다.

## 완료 순서와 상태
- 아래 블록 완료는 주문별 메뉴 줄에 제조 완료를 기록한다. 같은 조건의 2잔 작업이면 해당 두 주문의 라떼 줄을 함께 표시한다. 주문 상태는 `waiting/in_progress/done` 중 기존 값을 유지한다.
- 완료된 메뉴 줄은 위 주문서에서 가로선을 긋는다. 다른 메뉴 줄은 정상 표시한다. 아래 블록도 `완료됨`으로 보여 재클릭하지 않게 한다.
- 위 주문서 `완료`를 먼저 누르면 그 주문은 보드에서 빠진다. 그 주문의 메뉴 수량은 아래 남은 작업에서 뺀다. 예: `#126·#128 라떼 2잔`을 누르기 전에 #126 주문서를 완료하면 `#128 라떼 1잔`만 미완료로 남고 완료 표시를 붙이지 않는다.
- 주문서 전체 완료는 다른 주문의 메뉴 줄이나 다른 작업 블록을 제조 완료로 표시하지 않는다. 위 주문서 완료 자체는 아래 미완료 작업 때문에 막지 않는다.
- 현재 주문/묶음이 바뀌어도 아직 보드에 남은 주문별 메뉴 제조 완료 기록은 유지한다. 새로 들어온 주문의 같은 메뉴는 새 미완료 작업이다. 시나리오 초기화 시 제조 완료 기록도 초기화한다.

## 범위
- `teamktb`: 아래 작업 카드 생성, 메뉴별 완료 상태, 완료 API, UI 블록 및 버튼, AI 응답 파서·계약 문서, 관련 테스트.
- `aiserver`: 메뉴별 제조 호환성 응답 추가와 해당 테스트. Zoro 질문의 범위는 기존 메뉴 쌍 비교를 재사용한다.
- 1행 주문서의 메뉴 글자 크기·배치 변경은 이번 범위 밖이다.
- 빠른 주문 카드의 `내줬어요`와 주문 처리 동작은 유지한다.

## 완료 기준
- 메뉴가 둘 이상이면 각각의 작업 블록과 완료 버튼이 보인다.
- 한 블록 완료 시 해당 주문들의 해당 메뉴 줄만 가로선으로 표시되고, 주문 전체 완료 상태와 다른 메뉴 줄은 그대로다.
- 주문서 완료 시 아래의 다른 미완료 메뉴 줄이 자동으로 제조 완료 처리되지 않는다.
- 주문서를 먼저 완료한 예시에서 남은 주문 분량만 새 미완료 작업으로 보인다.
- Zoro 확인 중·응답 실패·함께 만들 주문 없음 상태에서도 현재 주문의 메뉴별 작업을 표시한다.
- 복합 주문의 일부 메뉴만 Zoro가 함께 제조 가능하다고 판단하면, 나머지 메뉴는 합친 작업에 넣지 않는다.
- 관련 주문이 바뀌면 작업 목록과 배분 수량을 다시 계산한다. 이미 완료한 작업 기록의 유지 규칙은 아래 질문의 답으로 확정한다.
- 기존 주문 완료와 빠른 주문 처리 테스트가 통과한다.
- 대시보드의 시연 장면에 `SC-W`(가칭)를 추가한다. 라떼 2건과 다른 메뉴 1건, 그리고 복합 메뉴 주문 1건으로 메뉴별 선택을 재현한다. Zoro 대역 서버 → aiserver → teamktb → 화면을 통과해 요청·응답, 두 블록, 한 블록 완료 후 주문서 가로선, 주문서 선완료 후 수량 변경을 확인한다. 대역 결과를 실제 Zoro 판단이라고 표시하지 않는다.

## 사용자 답변 반영
1. 같은 메뉴·옵션 작업을 누르면 관련 주문의 해당 메뉴 줄 전체를 한 번에 완료한다. 사용자가 #126·#128 라떼 2잔 예시로 확정했다.
2. 주문서를 먼저 완료해 보드에서 빠진 주문의 메뉴 수량은 빼고 남은 주문 분량만 미완료로 보여 준다.

사용자 승인 후 두 저장소에서 구현하고 로컬 시연 장면으로 확인했다.
